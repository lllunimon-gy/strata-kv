# v0.4 性能回退复查与 v0.4.1 优化

作者：gy

## 测量方法

三个版本在同一台 macOS runner、同一 Swift 工具链上构建；使用完全相同的探针源码。每版预热 1 轮，随后交替运行 6 轮，每轮都创建新目录，六种执行顺序平衡先后位置。
候选代码：`13d32d779e7884676c54a5efa9901929786a4e29`；[CI](https://github.com/lllunimon-gy/strata-kv/actions/runs/38919451321)；[完整原始数据](Results/v0.4.1-same-host.json)；[复现脚本](compare.py)。

表中单位为微秒，P50/P99 是“各轮对应分位数的中位数”，不是把全部样本合并后的分位数。变化率相对同机 v0.4；负数表示降低。
主测试未装入阶段回调；阶段剖分另行运行。读取/重开是热缓存。10,000 活跃 key 压缩每轮仅测一次，不能把它的 P99 当成尾延迟。

## 分阶段观察

每批 10 个 256 B 值，1,000 个同步提交，使用相同 fault 回调标记四个边界。该路径刻意保留三次写入，因此不包含新版正常路径 writev 的收益。

| 阶段 | v0.2 P50 | v0.4 P50 | v0.4.1 P50 |
|---|---:|---:|---:|
| encode-lock-header | 45.812 | 31.334 | 28.625 |
| payload-write | 5.875 | 7.854 | 6.792 |
| trailer-write | 2.396 | 2.479 | 2.417 |
| sync | 88.375 | 106.688 | 92.625 |
| publish | 3.562 | 4.187 | 4.208 |

encode-lock-header 包含验证、编码、锁和头部写入；publish 包含索引发布和返回路径。不能将它们叫作纯 CPU 编码时间或纯锁耗时。各阶段分位数也不能相加推导总分位数。

## 代码层面的原因与处理

| 问题 | 本次改动 | 正确性边界 |
|---|---|---|
| v0.4 普通同步提交多次进入索引锁 | 捕获写入位置/序号共用一次锁，统计和索引一起发布；普通无轮转提交缩为两次 | 仍由写者锁串行；pread 与磁盘写入不持索引锁 |
| 头、正文、提交尾分别发起 write | 正常路径用 writev；无完整拼接副本，处理短写与 EINTR | writev 不代表事务或落盘；CRC/提交尾、fsync 和失败后 reopen 仍保留 |
| 每个整数字段构造小 Data/临时数组，正文动态扩容 | 直接追加小端整数，验证后预留正文和变更表容量 | 磁盘格式不变，快慢路径字节一致 |
| GroupedWriter 接纳和提交各完整编码一次 | 接纳仅验证并计算字节，提交再编码并校验实际 revision | 大值/大批次、TTL 和 key 错误仍在接纳前拒绝；队列容量不变 |
| 已确认同步的活动段在轮转时再次同步 | 跟踪活动段是否仍需同步 | 缓冲写入、重开来源不确定的活动段仍必须同步 |
| 压缩发布逐 key 提取 URL 文件名 | FileRef 创建时保存文件名，比较已缓存字符串 | 旧快照仍保留描述符，不改变文件生命周期 |
| 打开已有 manifest 时重复读取和 JSON 解码 | 传递已经验证的 manifest 给恢复过程 | 缺清单、CRC、文件名和序列验证保持 |

## 没有用来换性能的部分

没有关闭校验、取消关键目录同步、降低默认持久性或让读取看到未提交值。旧 v0.2 压缩是阻塞重写单文件；v0.4/v0.4.1 需要先轮转增量段，再发布 checkpoint 和增量清单，固定成本更高。小数据库压缩不一定比 v0.2 快，不能抹去这个架构取舍。
读取的 TTL 时间判定、版本信息和文件引用维护仍保留。本次没有为了微秒级读延迟回退到用同一把锁包住磁盘读写，也没有加入难以证明一致性的缓存。

## 验证

51 项单元/边界测试、12 个子进程中断场景、iOS 示例构建通过；15 项引擎测试通过 Thread Sanitizer。新增测试覆盖：向量短写/跨缓冲区推进/EINTR/零写/ENOSPC、快慢路径字节一致、边界预验证、同步与缓冲轮转及重开后的同步决策。
ENOSPC 通过底层写入适配器注入；没有实际填满设备磁盘。仍不等价于真机断电或文件系统错误验证。

## 复现

```sh
python3 Benchmarks/compare.py --workspace /tmp/strata-compare-new --output comparison.json --rounds 6
```

需要 macOS 和完整 Git 历史。脚本在新工作目录克隆并构建指定提交，只替换克隆内的命令行探针，不修改原仓库。全部轮次保留；不因结果不好而挑选重跑。
